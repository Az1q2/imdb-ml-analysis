# IMDb ML Analysis: Поиск кинематографических шедевров и детекция аномалий

ML-пайплайн для работы с зашумленными данными IMDb: оптимизация памяти, выявление аномалий и накруток без учителя (Unsupervised), а также классификация экстремально редких событий (Imbalanced Rare-Hit Classification).

---

## 1. Постановка задачи и проблема

* **Исходные данные**: сырой дамп IMDb объемом ~12.8 млн записей (`title.basics` и `title.ratings`).
* **Проблемы данных**:
  1. **Экстремальный шум и накрутки**: тысячи любительских картин с оценкой `10.0` при $5–10$ голосах от знакомых автора.
  2. **Экспоненциальный масштаб**: разброс голосов от 5 до 3 000 000+, делающий стандартные метрики расстояний и линейные модели неэффективными.
  3. **Экстремальный дисбаланс**: объективный целевой класс «шедевр мирового кино» составляет всего **0.177%** выборки (555 фильмов из 313 025, соотношение **1 : 563**). Банальный классификатор с константным нулём дает Accuracy 99.82%, но не решает задачу.

---

## 3. Фаза 1: Оптимизированный ETL и Feature Engineering

### Почему сделан такой выбор:
* **Экономия памяти (13.4 МБ вместо гигабайт)**:
  * Использован параметр `usecols` для чтения только необходимых полей.
  * Первичная фильтрация `titleType == 'movie'` выполняется до слияния.
  * Числовые типы приведены к пониженной разрядности: `float32` для рейтингов, `int16` для годов и хронометража, `category` для строковых категорий.
* **Inner Join по `tconst`**: отсекает миллионы картин без оценок, так как без пользовательского отклика невозможно выявлять паттерны и строить предиктивные модели.
* **Фильтрация выбросов входных данных**: отсечены технические артефакты (года вне диапазона 1890–2026 и хронометраж вне 20–400 минут).

### Новые признаки (Feature Engineering):
* **`log_votes` = $\log_{10}(\text{numVotes})$**: сжимает экспоненциальный разброс голосов ($5 \dots 3 \cdot 10^6$) в компактный диапазон $0.7 \dots 6.5$. Без этого деревья решений и метрические методы смещаются исключительно в сторону мейнстримных блокбастеров.
* **`rating_to_log_votes`**: маркер накрутки рейтинга при единичных оценках. У накрученных картин этот коэффициент экстремально высок ($> 10$), у признанных шедевров находится в контролируемом балансе ($1.2 \dots 1.6$).
* **`movie_age`**: возраст фильма для учета временного горизонта признания картины.

## 4. Фаза 2: Детекция аномалий без учителя (Unsupervised Anomaly Detection)

### Почему сделан такой выбор:
* **`RobustScaler` вместо `StandardScaler` / `MinMaxScaler`**:
  * `StandardScaler` использует среднее и стандартное отклонение, которые сами сильно смещаются под действием аномалий.
  * `RobustScaler` центрирует данные по **медиане** и масштабирует по **межквартильному размаху ($IQR = Q_{75} - Q_{25}$)**, что сохраняет истинную форму распределения без влияния редких экстремальных точек.
* **`Isolation Forest` вместо `Local Outlier Factor (LOF)`**:
  * LOF имеет вычислительную сложность $O(n^2)$ по расчету $k$-ближайших соседей, что неприменимо для 313 тыс. строк.
  * Isolation Forest работает за $O(n \cdot \log n)$, изолируя аномалии в неглубоких листьях случайных бинарных деревьев (аномалии требуют значительно меньше разбиений, чем объекты плотных кластеров).
  * Параметры: `n_estimators=100`, `contamination=0.01` (ожидаемый объем шума 1%), `n_jobs=-1`.

### Результат:
Сформирован непрерывный признак `score_iforest` — степень изолированности фильма, который передается на следующий этап в качестве дополнительной фичи для классификатора.

## 5. Фаза 3: Классификация редких событий (Imbalanced Rare-Hit Classification)

### Целевой класс:
* **`is_masterpiece`**: рейтинг $\ge 8.0$ при числе голосов $\ge 25\,000$.
* Всего объектов: **555 из 313 025 (0.177%)**. Дисбаланс: **1 : 563**.

### Архитектурные решения:
1. **`Stratified Split` (80% train / 20% test, `random_state=42`)**:
   * Обычный случайный сплит при дисбалансе $1:563$ создает риск нестабильного попадания редкого класса в тест.
   * Стратификация гарантирует строго одинаковую долю $0.177\%$ в обеих выборках (Train: 444 шедевра / 250 420 фильмов; Test: 111 шедевров / 62 605 фильмов).
2. **`HistGradientBoostingClassifier` со встроенным `class_weight='balanced'`**:
   * **Скорость**: обучение заняло **0.58 секунды** на 250 тыс. строк благодаря гистограммному биннингу непрерывных признаков (256 бинов).
   * **Работа с дисбалансом**: штраф за ошибку на редком классе автоматически масштабируется обратно пропорционально частоте ($w_1 / w_0 \approx 563$). Это исключает необходимость в оверсэмплинге (SMOTE), который размывает топологию экстремально редких событий синтетическими точками.
3. **Выбор метрики: `PR-AUC` (Average Precision) вместо `ROC-AUC`**:
   * При дисбалансе $1:563$ метрика ROC-AUC дает ложно оптимистичную картину ($1.0000$), так как знаменатель False Positive Rate включает в себя 62 494 объектов отрицательного класса.
   * PR-AUC фокусируется исключительно на классе меньшинства, оценивая баланс между точностью и полнотой.

## 6. Результаты и метрики

### Тестовая выборка (62 605 фильмов, из них 111 шедевров):

| Метрика | Значение модели | Случайный Baseline |
| :--- | :---: | :---: |
| **PR-AUC (Average Precision)** | **0.9953** | 0.0018 (прирост в 550 раз) |
| **ROC-AUC** | **1.0000** | 0.5000 |
| **Recall (Полнота по шедеврам)** | **100.0% (111 из 111)** | — |
| **Precision (Точность)** | **87.40%** | 0.18% |
| **F1-Score** | **0.9328** | — |
| **False Negatives ($FN$)** | **0** | — |
| **False Positives ($FP$)** | **16** | — |

### Permutation Importance (вклад в падение PR-AUC на тестовой выборке):
1. **`log_votes`**: $+0.9920 \pm 0.0035$ — главный фактор (широкое социальное признание).
2. **`rating_to_log_votes`**: $+0.7929 \pm 0.0133$ — корреляция высокого балла с объемом голосов.
3. **`score_iforest`**: $+0.0498 \pm 0.0141$ — подтверждение вклада изолирующего леса без учителя.
4. **`runtimeMinutes`**: $+0.0004 \pm 0.0007$ — нейтральный фактор.
5. **`movie_age`**: $-0.0002 \pm 0.0008$ — возраст фильма не определяет качество картины.
